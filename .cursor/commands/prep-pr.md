# PR 올리기 전 점검

변경된 파일들을 PR 올리기 전 점검해줘.

## 절차

1. `git status`와 `git diff`로 변경 범위를 파악한다.
2. `npm test`를 실행하고 결과를 요약한다.
3. 테스트가 통과하면 변경 사항을 한국어 3줄로 요약한다.
4. Conventional Commits 형식(`feat:`, `fix:`, `chore:`, `refactor:`)으로 커밋 메시지 제목 1줄 + 본문을 제안한다.
5. 마지막에 리뷰어가 특히 봐야 할 부분을 짚어준다.

## 보고 형식

아래 순서와 형식으로 응답한다.

### 1. 테스트 결과

- 실행 명령: `npm test`
- 통과/실패 여부
- 실패 시: 실패한 테스트와 원인 요약

### 2. 변경 사항 요약 (테스트 통과 시만)

한국어 3줄:

1. (첫 번째 줄)
2. (두 번째 줄)
3. (세 번째 줄)

### 3. 커밋 메시지 제안

```
<type>: <제목>

<본문 — 변경 이유와 핵심 내용>
```

### 4. 리뷰 포인트

리뷰어가 특히 확인해야 할 파일·로직·엣지 케이스를 bullet로 정리한다.

## 금지

- 테스트 실패 상태에서 커밋·PR 생성을 진행하지 않는다.
- 사용자가 요청하지 않은 파일 수정·커밋·푸시는 하지 않는다.
