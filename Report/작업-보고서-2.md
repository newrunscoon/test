## 1. `Docs/validator.js` 추가

### 1.1 배경

`getValidEmails`의 필터링 로직을 재사용 가능한 유틸 패턴으로 분리하기 위해 `Docs/validator.js`를 추가함.

### 1.2 구현

```javascript
function filterValid(items, validator) {
    if (!Array.isArray(items)) {
        return [];
    }
    return items.filter(validator);
}
```

- 입력이 배열이 아니면 `[]` 반환.
- 배열이면 `validator` predicate를 통과한 항목만 반환.

## 2. `getValidEmails` 리팩터링

### 2.1 변경 전

```javascript
function getValidEmails(users) {
    return extractEmails(users).filter(isValidEmail);
}
```

### 2.2 변경 후

`Docs/validator.js`의 `filterValid`를 사용하도록 변경.

```javascript
const { filterValid } = require('../Docs/validator');

function getValidEmails(users) {
    return filterValid(extractEmails(users), isValidEmail);
}
```

### 2.3 데이터 흐름

```
users (배열)
  │
  ▼
extractEmails(users)  →  [email1, email2, email3, ...]
  │
  ▼
filterValid(emails, isValidEmail)  →  [유효한 email만]
  │
  ▼
getValidEmails 결과 반환
```

## 3. `isValidEmail` RFC 5322 정규식 적용

### 3.1 변경 전

```javascript
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```

기본적인 `@` 및 `.` 존재 여부만 검사하는 단순 패턴.

### 3.2 변경 후

[emailregex.com](https://emailregex.com)의 **RFC 5322 Official Standard** 패턴을 적용.

```javascript
const RFC5322_EMAIL_REGEX = /^(?:[a-z0-9!#$%&'*+/=?^_`{|}~-]+(?:\.[a-z0-9!#$%&'*+/=?^_`{|}~-]+)*|"(?:[\x01-\x08\x0b\x0c\x0e-\x1f\x21\x23-\x5b\x5d-\x7f]|\\[\x01-\x09\x0b\x0c\x0e-\x7f])*")@(?:(?:[a-z0-9](?:[a-z0-9-]*[a-z0-9])?\.)+[a-z0-9](?:[a-z0-9-]*[a-z0-9])?|\[(?:(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.){3}(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?|[a-z0-9-]*[a-z0-9]:(?:[\x01-\x08\x0b\x0c\x0e-\x1f\x21-\x5a\x53-\x7f]|\\[\x01-\x09\x0b\x0c\x0e-\x7f])+)\])$/i;
```

### 3.3 지원 범위

| 항목 | 설명 |
|------|------|
| 로컬 파트 | 영숫자 및 `!#$%&'*+/=?^_\`{|}~-` 등 RFC 허용 문자 |
| 따옴표 로컬 파트 | `"..."` 형식의 quoted-string 지원 |
| 서브태그 | `user+tag@domain.com` 형식 (`+` 포함) |
| 도메인 | 라벨 기반 도메인 (`example.com`) |
| IP 리터럴 | `[192.168.0.1]` 형식 |
